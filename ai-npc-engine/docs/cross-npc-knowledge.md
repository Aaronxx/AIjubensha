# 跨NPC知识共享系统 — 设计要点

> 状态：远期设计（多人模式阶段）
> 来源：主人提出 — NPC不应编造已有人物的不存在行为，且集体对话中需要知识传播与甄别

---

## 核心问题

1. NPC 在集体对话中得知其他 NPC 透露的信息后，应更新自己的知识库
2. 玩家说的话只有真实的部分才能被 NPC 记录
3. NPC 之间自然传播信息，形成"活"的群聊

---

## 设计

### 共享知识池（Group Knowledge Pool）

```
每一局游戏维护一个"群聊知识池"：
  {
    "fact_id": "k05",
    "content": "陈先生资金紧张想卖画",
    "revealed_by": "char_killer（周明远）",
    "revealed_at_round": 8,
    "verified": true,          ← 由系统核验：只有 NPC 知识库中存在的才算 verified
    "witnessed_by": ["char_01", "char_02"]  ← 哪些NPC在群聊中听到了
  }
```

### 玩家话语的真伪甄别

```
玩家说："陈先生的妻子威胁过苏晚晴"
  → 系统查 NPC 知识库：
    苏晚晴.fact_06 = "死者的现任妻子曾经威胁过我" → 真实 ✅
  → 标记 verified=true
  → 群聊中其他 NPC 记录："玩家声称陈太太威胁过苏晚晴——这一点是真的"

玩家说："陈先生欠了周明远五百万"
  → 系统查所有 NPC 知识库：
    无对应事实 → 无法验证 ❌
  → 标记 verified=false
  → 群聊中其他 NPC 记录："玩家声称陈先生欠周明远五百万——但这是玩家的推测，未必属实"
  → 如果玩家是编造假信息诈凶手，NPC 可以反驳："这我可没听说过"
```

### 信息传播规则

```
群聊消息 → 系统分析 → 提取事实断言 → 对比知识库

断言来源        验证结果       NPC知识库更新
─────────────────────────────────────────────
NPC透露         真实(源头)    所有在线NPC记录该事实
NPC透露         虚假(谎言)    凶手标记为谎言，其他人记录"X声称Y"
玩家透露        可验证为真    所有NPC记录该事实
玩家透露        无法验证      所有NPC记录"玩家声称X，未经证实"
玩家透露        可验证为假    凶手知识库有相反事实→可反驳玩家
```

### 对 NPC 行为的影响

```
NPC 在生成回复时，除了自己的知识库，还要参考：
  1. 自己的静态知识库（编剧设定）
  2. 群聊中已公开的 verified 事实（其他人透露的真相）
  3. 群聊中玩家声称的 unverified 断言

NPC prompt 增加：
  【群聊中已公开的事实】  ← 其他NPC透露的，你现在也知道了
  【玩家声称但未证实】    ← 你可以选择相信、怀疑或反驳
```

---

## 关联系统

- `src/models.py` → NPCState 需增加 `group_knowledge: list`
- `src/engine.py` → 增加 `GroupKnowledgePool` 类和真伪甄别逻辑
- `src/state_manager.py` → 增加跨NPC事实传播方法

## Why

避免 NPC "全知全能"（知道所有真相）或"全不知"（对其他NPC透露的信息充耳不闻）。
让群聊像一个真实的集体讨论，信息逐步扩散，每个 NPC 的认知动态演化。

## How to apply

多人模式开发时，将此设计作为群聊系统的核心模块之一。
