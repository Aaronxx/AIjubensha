## 一、实时模式 vs 明侦模式

```
明侦模式（阶段一）                    实时模式（阶段三）
─────────────────────                ─────────────────────
谋杀是"背景设定"                      谋杀是"正在发生的新闻"
时间线是"已经写完的历史书"            时间线是"正在播放的直播"
玩家是"考古学家"                      玩家是"战地记者"
问："谁杀了人？"                      问："正在发生什么？谁会杀人？"
NPC行动限于"对话中的反应"             NPC行动包括"真实世界中的行动"
搜证是"翻找过去"                      搜证是"追踪当下"
```

实时模式不是明侦模式的升级版，而是不同的物种。它把"推理"从静态拼图变成了动态追踪。

## 二、核心引擎：三层架构

### 2.1 第一层：预定义事件表

编剧为每个 NPC 预设"计划事件表"，每个事件标记属性：

- **硬性事件**：必须在某个时间窗内发生（如"尸体被发现"）
- **弹性事件**：可以延迟但不能取消（如"谋杀"）
- **可选事件**：取决于条件是否满足（如"与某人密谈"）

```
═══════════════════════════════════
  NPC 杀手 — 计划事件表
═══════════════════════════════════

20:00  抵达山庄，与众人寒暄
       → 条件：无
       → 与谁互动：所有人（群聊可见）

20:30  晚宴
       → 条件：无
       → 关键对话：暗示与死者的紧张关系

21:00  借口离席，去书房取"文件"
       → 条件：需在群聊中说"我先失陪一下"
       → 实际上：取藏好的凶器

21:15  前往死者房间实施谋杀 ← 核心事件
       → 条件：死者必须在房间内
       → 冲突检测：路径上是否有其他人？
       → 持续时间：5分钟（游戏内时间）

21:20  返回公共区域，建立不在场证明
       → 条件：谋杀已完成
       → 行为：主动与人攀谈，刻意提及时间

21:30  死者被发现 ← 硬性截止时间
       → 无论谋杀是否完成，尸体必须在此时之前被发现
═══════════════════════════════════
```

### 2.2 第二层：冲突检测系统

实时轮询所有玩家的位置和行动，与 NPC 计划事件表做碰撞检测：

```
冲突类型：

类型A — 空间冲突（玩家挡住了NPC的行动路径）
  NPC计划：21:15 前往死者房间
  玩家状态：21:14 正在走廊上与另一NPC交谈
  → 冲突！→ 进入"重排决策"

类型B — 互动冲突（玩家正在与NPC互动，该NPC有即将发生的计划事件）
  NPC计划：21:15 离开去实施谋杀
  玩家状态：21:13 正在与该NPC私聊
  → 冲突！→ NPC需要找理由脱身

类型C — 见证冲突（玩家处于可目击关键事件的位置）
  NPC计划：在书房窗口传递凶器
  玩家状态：正在花园散步，正好能看到书房窗口
  → 冲突！→ NPC可能注意到玩家，改变计划

类型D — 无冲突
  玩家的行动完全不干扰NPC的计划
  → 事件按计划发生
```

### 2.3 第三层：动态重排决策

当冲突发生时，AI NPC 需要做出"重排决策"。

决策由编剧预设的**重排优先级**控制，并非 AI 自由发挥：

```
重排决策树（以谋杀被阻挡为例）

冲突：玩家在杀手必经之路上
  │
  ├── 方案A：等待
  │   "看到走廊有人，退回房间等待"
  │   谋杀延迟 5-10 分钟（游戏内时间）
  │   风险：时间窗口缩窄，可能与其他事件冲突
  │
  ├── 方案B：改道
  │   "从另一侧的楼梯绕过去"
  │   谋杀照常发生，但路线不同 → 留下不同的线索
  │   风险：新路线可能被其他人目击
  │
  ├── 方案C：改地点
  │   "目标离开了房间...跟着他到别处动手"
  │   谋杀在新的地点发生 → 搜证阶段的位置信息变化
  │   风险：新地点可能不利于掩盖证据
  │
  └── 方案D：放弃本轮（极少使用，仅限极端情况）
       "今天不是动手的时机"
       谋杀推迟到更晚的时间，或改变作案手法
       风险：如果到"硬性截止时间"还未动手 → 触发替代剧本线
```

**编剧配置示例：**

```
杀手NPC — 谋杀事件的重排配置：

优先级1：等待（延迟≤15分钟）
优先级2：改道（替代路线：A/B/C）
优先级3：改地点（替代地点：书房/地下室）
放弃：仅在"所有替代方案不可行 + 硬性截止剩余<5分钟"时触发
```

## 三、两条设计金线

### 3.1 金线一：谋杀一定发生

在明侦模式中，尸体开局就躺着了。在实时模式中，需要确保玩家的行动不会导致"无限期无案件"。

**解决方案：双轨剧本线。**

```
主线（谋杀发生）：
  └─ 玩家经历事件 → 谋杀发生 → 调查 → 投票
  └─ 这是"正常"的游戏流程

替代线（谋杀未遂）：
  └─ 玩家的行动导致谋杀被阻止
  └─ 系统自动触发"替代事件"
     例如：杀手被逼到绝路，攻击了玩家 → 玩家受伤但幸存
     例如：杀手的计划被打乱，露出了马脚 → 另一桩罪行暴露
  └─ 最终：玩家仍然需要推理"谁是幕后黑手"
     但核心事件从"谋杀"变成了"谋杀未遂 + 其他罪行"
  └─ 稀有结局，发生率 < 5%

替代线的设计原则：
  - 不强制——玩家行动自然导致的结果
  - 仍然有"案件"可推理（未遂也是案件）
  - 玩家感觉"我阻止了一场谋杀"而非"游戏出了Bug"
```

### 3.2 金线二：时间在分幕中压缩

游戏内时间和现实时间不是1:1的：

```
游戏内时间轴（示例）：

20:00 ───── 21:00 ───── 21:30 ───── 22:00
  第一幕      第二幕       第三幕
  (15分钟)    (20分钟)     (25分钟)    ← 现实时间
  =30分钟      =90分钟      =60分钟     ← 游戏内时间

时间压缩比：1:2    1:4.5       1:2.4
```

分幕之间可以跳过大段的"游戏内时间"，只在关键时间窗口展开实时互动。
玩家感觉经历了整个夜晚，但实际上只在关键时刻"驻足"。

## 四、对现有系统的影响

| 子系统 | 明侦模式 | 实时模式的变化 |
|--------|---------|--------------|
| 搜证系统 | 搜索历史痕迹 | 增加"观察当前行为"、"跟踪"、"蹲守"等实时调查动作 |
| NPC对话 | 质问过去 | 增加"试探即将发生的事"、"紧急打断"等对话类型 |
| 分幕结构 | 搜证轮→讨论轮 | 时间推进更自然，幕间是"时间跳跃"而非"搜证轮" |
| 短剧 | 事件后播放 | 可在"事件前"给玩家预感（如杀手准备凶器的画面） |
| 复盘系统 | 蝴蝶效应基础版 | 完整因果图 + "如果你当时选了X，谋杀会在Y处发生" |
| 叙事保护 | 几乎不需要 | L1-L4完整保护机制 |

## 五、为什么放在阶段三

```
实时模式的价值不在"技术难度"，而在"体验独一无二"：

  明侦模式：
    玩家说"我推理出了谁是凶手"
    → 满足感来自智力

  实时模式：
    玩家说"我差点就能阻止他了"
          "如果我当时跟着他而不是回房间..."
          "凶手刚才就坐在我对面，我们还在聊天气"
    → 满足感来自智力 + 情感 + 遗憾 + 庆幸
    → 电影级的情感体验

前置依赖：
  需要明侦模式先验证 AI NPC 的基础能力
  （对话有趣、人格一致、推理有深度）
  然后才能承载实时模式的复杂性
  如果 NPC 本身不有趣，实时模式再酷也没人玩
```
